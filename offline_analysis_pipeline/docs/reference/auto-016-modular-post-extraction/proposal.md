# Proposal

Owner：当前对话用户（2026-10-17 明确要求继续本 Change 实施）。

## Why

当前 V2.1 把证据定位、实体识别、主张拆分、事件识别、作者信息和摘要放在一次调用中。近期抽检发现非连续证据、省略号拼接、车型层级误判、作者信息过推，以及事实与观点混合。问题无法定位到单一环节，也会把低价值表达带入结果。

本 Change 将范围收窄为“单贴信息抽取”：先保留可回挂证据，再在同一帖子内完成保守的对象和命题整理，输出供下游分析使用的中间包。比较关系只是单贴命题的一个可选关系字段，不建立跨贴分析、推荐或决策层。

## What Changes

- 先形成保留V2.1全部定义的完整改进契约 `prompts/full-v2.2.md`，修正语义错误边界；再按契约生成阶段Prompt和逐节迁移记录，不用精简枚举表代替完整定义。
- 当前已批准字段修订版为 `prompts/full-v2.3.md`：experience_basis替换experience_type，comparison保留在claim内并支持多对象关系，sentiment_intensity替换sentiment_score，增加claim.usage_context；新输出Schema为2.3，旧结果保持原版本。
- 新增三个最小阶段：确定性输入/证据准备、候选证据抽取、单贴命题与对象整理。
- 候选阶段输出可回挂到真实block的连续证据、原始提及、说话者/来源；不要求最终分类，不生成摘要、人格画像或确定车型。后续整理读取完整原帖并允许补回候选遗漏。
- 单贴整理阶段保守处理车辆、非整车对象、事件提及、体验/问题/需求/评价和比较关系；比较只记录同一帖子明确出现的对象、方面和方向，不产生综合优劣或购买建议。
- 事件作为帖子中的外部事项记录并带摘要；作者对事件的态度另记为命题，不自动建立因果关系。
- 增加阶段版本、输入哈希、提示词/模型指纹、缓存命中和失败原因，支持从失败阶段续跑。
- 增加证据回挂、ID、枚举和引用关系质量门；引用允许代码对少量空白/标点/同一block有序省略号做保守兜底，其他字段不自动修复。保留V2.1历史读取能力，新字段不得伪装为旧版或由旧分数/情境猜测补齐。
- 默认采用当前完整图文整合数据 `collaboration/data/004_A4_图片策展_主链路终版.csv`，固定种子 `20261016` 随机抽取 100 条做首轮验证；不把该样本当作全量准确率。
- 本 Change 不做跨帖子聚合、全局车辆知识库、外部事实核验、产品推荐、决策支持或全量重跑，不修改历史输出。

## Capabilities

### New Capabilities

- `modular-post-extraction`: 以证据为中心的单贴分阶段抽取、缓存、质量门和 V2.1 兼容适配。

### Modified Capabilities

- 无。当前 `openspec/specs/` 没有已登记的正式能力规格；本 Change 先建立新能力契约。

## Impact

- 影响 `tools/` 下的 Qwen 调用、缓存和校验逻辑，以及 `collaboration/result/` 的运行记录组织方式。
- 新增内部中间JSON和阶段manifest；新输出Schema 2.3保留九根字段，claims子结构存在明确不兼容变更。
- 使用现有 Qwen API 和本地缓存，不新增供应商或数据库依赖。
- 成本风险：阶段化可能增加调用数；通过条件执行、压缩候选、缓存和 100 条固定样本对照控制并实测 token/延迟。
- 授权记录：当前对话用户已明确“开始实现”，后于“先改进完整Prompt、再划分职责与拆分”说明后确认“对，继续。”；支持本Change本地实现与Prompt修订，不等于代码验收或合并。人类Owner实名、审阅commit和最终交付审阅仍待登记。

## 2026-10-17 已授权补充：全量失败修复与定向重跑

用户明确要求对 `single-v23-full` 中此前契约失败的记录先用代码修正，无法安全修正的检查根因并重跑。范围严格限定为已闭合的 554 条失败记录：9147 条既有通过记录不得重写、重跑或改变字节；原始调用目录、raw response 和现有 essential 包保持只读。

代码修正只允许不改变抽取语义的确定性白名单：唯一可证明的证据 block 错挂、仅 Unicode 空白/标点造成的连续证据格式差异，以及由调用目录、冻结输入和请求指纹共同确认的 `post_id` 抄写错误。歧义 block、改写/跨句拼接证据、未知引用、比较关系、情感强度和截断输出不得猜测修复。

无法通过白名单修复的记录独立写入 `single-v23-full-repair1`，沿用冻结的 V2.3 Prompt、Schema、模型和输入，每帖显式重跑一次；不隐式二次重试，不用新增样本替换失败。重跑结果仍需通过本地完整契约，剩余失败保留根因和审阅材料。用户本轮“继续”确认上述 OpenSpec 增量并授权此限定实施；这仍不等于语义准确率验收、代码交付验收或合并授权。
