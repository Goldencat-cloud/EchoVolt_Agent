# 执行分析计划

## 角色与读者

服务对象：处于执行阶段的 Agent。输入：已获批的计划（workstreams 列表）。输出标准：每项 workstream 要么有可核验的执行结果，要么有如实记录的放弃原因——没有第三种状态。

## 执行循环（逐项执行，完成一项再取下一项）

1. **取项执行**：按该项在计划里声明的 method 调用对应工具，参数从计划原样抄写。计划边界与工具边界由工具强制；此处只提醒一条判断：`python_analyze` 是白名单之外的交叉与补充，不替代计划声明的方法。
2. **取证**（计划标注了证据需求的工作项，或任何需要引文佐证结论的时刻）：走哪个工具、怎么去重、引文怎么挑，读 `reference/collect-evidence.md`。
3. **解读三关**（结果落账前逐条自问——这是执行与报告之间唯一的解读关口）：
   - **事实还是推断？** 产品共现只说明"同帖出现"，不说成偏好或胜负；journey/ownership 是观点的属性，分布只说明"观点来自哪里"，不说成用户结构；缺失值保持"未标注"。
   - **集合标了吗？** 依据本次简报与工具返回标注集合：精选子集不说成全量，全量产品关联主张不说成精选；带时间过滤时注明区间。
   - **分母对了吗？** 观点级与帖子级占比不可互换，不用一个分母代算另一个。
4. **失败处置**：按系统提示的异常处理执行；仍失败 → 换计划内其他方法，或放弃该项并记录原因；错误预算用尽 → 停止重试。
5. **空结果处置**：方法执行成功但数据为空或不支持 → 先查过滤值是否来自目录枚举、时间是否在覆盖内；确属无数据则如实记录（算已执行），原因写进报告"限制"，不凑结论。
6. **图表产出**（计划声明了 `visualization` 的工作项）：把该项已验证的行数据转成 chart 结构，写法读 `reference/write-code.md`。**同源检查**：图表里每个数值必须与该项已验证步骤的行数据逐字一致——图表里编一个数等于正文编一个数，同样被拒。

## 完成检查（全部 workstream 走完循环后）

- [ ] 计划内每项都有结果或放弃记录，无第三种状态
- [ ] 需要证据的工作项都有带 `claim_id` 的证据账本记录
- [ ] 标记了 `visualization` 的工作项，图表数值与已验证行逐字一致

全部勾选后进入报告阶段。

## 禁止清单（判断类；机制类约束由工具与校验器强制）

- 口径判断：不把共现说成偏好；不把属性分布说成人群结构；不混用两级分母。
- 推进边界：某项失败不阻塞其余项；错误预算用尽则整体停止（机制见系统提示异常处理）。
