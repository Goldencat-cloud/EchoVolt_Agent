# 取证：需要引文时

## 何时用

计划标注了证据需求的工作项，或任何要引用原话佐证结论的时刻。

## 前提

计划声明的是**证据需求**（服务端已推导并标注），不是具体取证工具。在下面三种中**任选其一**：

| 工具 | 返回什么 | 何时用 |
|---|---|---|
| `top_negative_claims` | 议题的负向说法列表（claim_id + 短引文） | 要看"负向声音的清单"，按议题看模式 |
| `get_negative_evidence` | 议题的负面原文（quote/title/url/date，带 claim_id） | 报告要引用原话，需要完整引文与出处 |
| `search_claims` | 按结论关键词语义召回，不限情感 | 需要正面/中性对照，或按具体说法找样本 |

## 规则

- **同一议题只取一次**：三种工具返回的集合高度重叠，重复取证只会得到重复引文；要换视角就换问题，不是换工具。
- **议题必须在计划内**：越界会被拒（`evidence_not_in_plan`），这是授权闸，不是故障。
- **证据只说明"有人这样说"**：要数量就回到统计方法。
- **覆盖如实**：证据只覆盖精选子集，表述规则见报告阶段的口径节。

## 代表引文怎么选（最容易出错的地方）

- **3–5 条**足够：一条支撑一个说法，不堆砌。
- **覆盖 ≥ 2 种说法**：只引同一种抱怨，会让读者以为只有这一种。
- **不全部来自同一帖**：同一帖的多个观点只能算一个声音。
- **优先亲历**：明确自己经历过的表述 > 转述或推测。
- **保留反例**：若该组里存在相反说法的少数样本，提一句比藏起来可信。

- ✅ "4 条引文来自 3 个帖子、覆盖电池/售后两类抱怨（claim_id: a1…、b2…、c3…）"
- ❌ 8 条引文全部来自同一篇长帖（看起来证据充分，实际只有一个声音）

## 自查一句

每条引文都能回答："它来自哪个议题、哪条 claim_id、代表哪一类说法"——答不上就换一条。
