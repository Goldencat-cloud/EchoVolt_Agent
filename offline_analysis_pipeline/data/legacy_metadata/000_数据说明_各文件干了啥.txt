数据流水线说明（精简版）
====================================
文件名格式： 序号_阶段_这一步干了啥.csv
只保留每条分支链的**终点版本**；中间版本已逐列比对确认被完全覆盖、可由脚本重跑，故不对外同步。
这些 CSV 是从 data/processed/ 复制出来的**改名快照** —— 脚本仍依赖原文件名，别去改原文件。

只看数据就在这里；分析结果（EDA / 聚类 / 图片策展评估）见 ../eda/。

【流水线关系】

  A1   001 原始_论坛帖子数据 (9,994 行 × 25 列)
  A1   005 辅助_爬虫断点表   （旁支，20,187 行，只用于续爬）
         │
         ↓  A2 格式清洗 + A3 深度清洗（这两步的产物未入库，可脚本重跑）
  A3   002 深度清洗_全量_带噪声标注 (9,970 行 × 34 列)
         │  按 high_confidence 筛掉 269 行
         ↓  A4 下载图片 → 挂 image_id → 修正有效图引用 → 图片策展
  A4   004 图片策展_主链路终版 (9,701 行 × 27 列)  ★ 下游默认读它

  配套  A4   003 图片下载_图片清单 (22,116 行 = 一张图一行)

【保留的 5 个文件】

000_数据说明_各文件干了啥.txt       就是本文件

001_A1_原始_论坛帖子数据.csv               9,994 行 × 25 列   28.3 MB
    爬虫原始产出，一篇帖子一行。字段全是中文名（帖子标题/帖子链接/浏览数/回帖数/正文…），
    **没有 post_id 列**。回帖数、浏览数、图片数都还是带后缀的字符串（"214 回帖"），用之前要数值化。
    唯一不能再生的文件（重爬要凭证），务必留着。

002_A3_深度清洗_全量_带噪声标注.csv         9,970 行 × 34 列   50.7 MB
    全量分支终点。在 A2 清洗后的 23 列基础上，追加 11 个标注列：
    quality_score / high_confidence / is_duplicate / dedup_group_id / clean_text /
    norm_key / text_changed / clean_multimodal / excluded / non_chinese / is_long。
    含 `clean_text`（可直接喂 embedding 的干净正文）。**被 004 筛掉的 269 行也还在表内**，
    想自己定筛选阈值就用它。

003_A4_图片下载_图片清单.csv               22,116 行 × 9 列     5.7 MB
    图片清单表，**不是帖子表**，主键是 image_id。列：
    image_id, post_id, seq, url, local_path, status, size, error, dup_of。
    两份图库（data/images 与 data/images_removed）都靠它回挂，务必留着。
    其中 dup_of 非空 = 被判为冗余（真身图在 dup_of 里）；status 非 ok 的图不可用。
    注意：**图片本次未入库**（22,100 张 / 2.47 GB，分批提交），本表的 local_path
    在拿到图之前会指向不存在的路径，详见 ../PROGRESS.md。

004_A4_图片策展_主链路终版.csv              9,701 行 × 27 列   45.3 MB   ★
    主链路终点，下游分析/建索引默认读这个。含 post_id、title、clean_text、互动字段，
    比 002 多出 image_ids、image_local_paths 两列（JSON 数组）。
    已经过了：高置信筛选 → 挂图 → 有效图修正 → 图片策展（重复图/低相似图已移入 images_removed）。

005_辅助_A1_爬虫断点表.csv                 20,187 行 × 21 列   55.1 MB
    爬虫辅助表，**不是语料版本**，主键是 url。记录每条链接的抓取状态，用于断点续爬。
    不打算重爬可以无视。

【术语对照】（脚本与原文件名里还在用这些后缀）

    _clean     = 高置信子集（按 deep_clean 标注筛掉可疑行，9,970 → 9,701）
    _valid     = 有效图引用修正（实测只动了 8 行，没有整行删除）
    _imgid     = 挂载图ID（帖子表接上下载后的图片）
    _curated   = 图片策展（去掉重复图 / 低相似度图）

【怎么选文件】

  · 跑下游分析 / 建向量索引      → 004（文本用 clean_text）
  · 做图片描述 / 图片策展         → 004 + 003
  · 想自定义清洗阈值             → 002
  · 重跑爬虫                     → 005 放回 data/processed/ 当断点

【坑】

  · 全部是 utf-8-sig（带 BOM），pandas 的 read_csv 默认能处理；用 csv 模块手动读要指定
    encoding="utf-8-sig"。
  · post_id 有前导零，读取务必加 dtype={"post_id": str}，否则会丢零、对不上图。
  · **001 没有 post_id，主键是帖子标题，而且标题会重复**：9,994 行只有 9,759 个唯一标题，
    与 002 按标题只能对上 9,679 条（002 有 55 个标题在 001 里找不到）。
    要精确追溯来源必须走 002/004 的 post_id，别指望靠标题 join 回 001。
  · 002 与 004 的 post_id 完全对齐（9,701 个一致），这两份可以放心互 join。
  · 003 覆盖 5,817 个帖子（占 004 的 60%），其余 39% 的帖子本来就没图，join 时会有空值。
  · 003 的 local_path 是 Windows 绝对路径（D:\...），换机器后需重新映射。
