# Spec Delta

## Purpose

定义深度分析在开始执行前必须经过的人工大纲确认，确保系统内部不存在任何可自动批准该确认的代码路径，并规定等待审查期间的状态语义。

## ADDED Requirements

### Requirement: 人工确认不可绕过

系统 SHALL 保证深度分析在任何工具执行之前暂停并等待人工确认；任何内部调用路径 MUST NOT 以自动批准的方式继续。

#### Scenario: 等待审查时任务暂停

- **WHEN** 分析计划通过确定性校验
- **THEN** 任务进入「待大纲审查」状态并暂停，不执行任何分析调用

#### Scenario: 不存在自动批准入口

- **WHEN** 检查服务目录内可发起深度分析的代码路径
- **THEN** 所有路径均在人工确认处暂停，不存在以固定决策自动恢复的实现

### Requirement: 三种审查决定语义固定

系统 SHALL 支持「确认」「修改后确认」「驳回重拟」三种决定，并保持各自可观察的后果。

#### Scenario: 确认后按原计划执行

- **WHEN** 审查人选择确认
- **THEN** 执行阶段按原计划参数逐项执行

#### Scenario: 修改后以修改版执行

- **WHEN** 审查人修改计划后确认
- **THEN** 修改版重新通过同一套确定性校验，并以修改版参数执行

#### Scenario: 驳回让模型重拟

- **WHEN** 审查人选择驳回并给出意见
- **THEN** 任务不进入执行阶段，模型收到驳回意见并重新提交计划

### Requirement: 确定性预检先于人工审查

系统 SHALL 在把草案呈现给审查人之前先做确定性校验；未通过校验的草案 MUST 直接退回模型重拟，不得占用人工审查。

#### Scenario: 结构不合法的草案不进入人工

- **WHEN** 草案未通过确定性校验
- **THEN** 任务保持非待审状态，草案连同具体问题退回模型

#### Scenario: 重拟次数有上限

- **WHEN** 草案连续未通过校验达到上限
- **THEN** 任务以显式失败结束，并保留最近一次失败原因

### Requirement: 待审状态不占用执行资源

系统 SHALL 将等待人工确认的任务排除在并发执行名额之外，并以任务存储作为生命周期的唯一事实来源。

#### Scenario: 待审任务不阻塞新任务

- **WHEN** 已有一个任务处于待大纲审查
- **THEN** 新的深度分析请求仍可被受理

#### Scenario: 会话丢失时显式失败

- **WHEN** 恢复请求找不到对应的任务会话
- **THEN** 系统返回显式失败，而不是静默重新开始分析
