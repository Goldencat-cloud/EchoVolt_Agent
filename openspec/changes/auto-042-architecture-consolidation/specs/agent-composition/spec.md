# Spec Delta

## Purpose

定义 agent 的运行姿态与唯一装配入口，使「预算、可用工具、可加载技能、是否需人工审批」只能由配置数据决定，而不散落在多个调用点。

## ADDED Requirements

### Requirement: agent 构造只有一个入口

系统 SHALL 经由唯一装配入口构造 agent 及其运行状态；业务调用点 MUST NOT 自行构造 agent 或自行拼装其依赖。

#### Scenario: 新增调用点不得自建 agent

- **WHEN** 检查服务目录内除装配模块以外的源码
- **THEN** 不存在任何 agent 构造调用

#### Scenario: 两条生产链路共用装配

- **WHEN** 分别发起一次对话请求与一次深度分析任务
- **THEN** 两者的 agent 均由同一装配入口产生，预算、工具集与门禁配置来自同一份姿态声明

### Requirement: 运行姿态是配置数据

系统 SHALL 以配置实例声明每种姿态的预算、工具白名单、技能集合、产物类型、失败语义与审批要求；MUST NOT 在调用点硬编码上述任何一项。

#### Scenario: 预算只有一处定义

- **WHEN** 修改某姿态的工具调用上限
- **THEN** 该姿态下所有链路同时生效，无需修改工具实现

#### Scenario: 工具白名单按能力表达

- **WHEN** 姿态声明允许「读取」与「计算」能力
- **THEN** 展开为该能力下的全部已登记工具，无需逐一列举工具名

#### Scenario: 新增姿态不新增分支

- **WHEN** 需要一个新姿态
- **THEN** 只新增一份配置实例并通过构造期校验，不新增调用点分支代码

### Requirement: 装配期自洽性校验

系统 SHALL 在构造姿态时拒绝不自洽的配置，而不是在运行期暴露。

#### Scenario: 白名单引用未登记工具

- **WHEN** 姿态声明的工具白名单包含未登记工具
- **THEN** 构造期即失败并指出未登记项

#### Scenario: 报告姿态缺少审批要求

- **WHEN** 某姿态声明产出报告但未声明人工审批
- **THEN** 构造期即失败

#### Scenario: 预算与递归上限矛盾

- **WHEN** 姿态的调用预算超过图递归上限所能提供的轮次
- **THEN** 构造期即失败

### Requirement: 技能按姿态注入

系统 SHALL 只向 agent 注入其姿态声明的技能；声明的技能不存在时 MUST 在构造期失败。

#### Scenario: 未声明的技能不可见

- **WHEN** 某姿态只声明入口技能
- **THEN** 该姿态的 agent 只能发现并加载入口技能，不能加载其他姿态的技能

#### Scenario: 技能缺失立即失败

- **WHEN** 姿态声明的技能目录不存在
- **THEN** 构造期失败并指出缺失的技能名
