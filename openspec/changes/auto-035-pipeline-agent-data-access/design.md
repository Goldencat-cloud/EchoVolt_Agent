# Design

## Context

现有 `research/service.py` 指向 06 旧 analysis 与 agent-kb 的 data-version；`db_mirror.py` 从旧导出构造语义视图，存在时直接复用镜像。新管道 `pipeline-01-06` 源提交为 e9c10ec0bdd1b9156a37ee8727f7757ba04ccd1f；README 声明 `v_claims_canonical` 的粒度为主张×实体，`extracted_claims` 与 `extracted_evidence` 包含 run_id。旧的 auto-030/031/032 尚未归档；用户已取消其他负责人审阅，相关兼容性须由实施验证。

新管道源 worktree 的 `offline_analysis_pipeline/data/stock/db/ingestion.sqlite3` 由 Git LFS 提供，sha256 `a45e3f11bea01c4039072784d2870824f35293b5120fec7fb3f03d9785bdc02b` 与 LFS 指针一致；quick_check 通过且外键检查无结果。包括 27,000 claims、57,863 evidence，18 个增量 passed。报告所记数据库 SHA256 为 `e6d0614fd1fb985fcb4c65472425184acb398055f2d865632554e6209ec60a68`，与当前文件不同，不宣称字节一致。本地 Agent worktree 内的 stock 数据库缺少抽取与归一化表，不能用于本次实例。

隔离准备：历史单帖结构验证副本仅用于探索，不能作为完整批次统计。对真实数据库 18 帖增量在内存重建 pack，18 个模型输入指纹一致；76 条 Claim 引文中 61 条符合 06 报告严格匹配，余 15 条只符合 04 抽取较宽松匹配。两者状态不可混同，语义准确率未测。当前未发现单帖多个已拍平 run；上游 `MAX(run_id)` 策略在多 run 场景仍须防护。

## Goals / Non-Goals

**Goals:** 直接对接动态标准化数据库，保留现有分析方法并统一采用全量口径，完成逐次大纲审查后的自动正式报告及一次真实 Agent 分析，并复算结果。

**Non-Goals:** 不触发全量抽取或归一；不扩展多品牌能力；不做公开部署。

## Decisions

1. 新管道数据库保持动态更新；Agent 通过只读连接读取已提交且完成处理的数据，不要求维护固定数据库版本。旧 `PipelineSnapshot` 的固定 SHA 和禁止非空 WAL 与此方向不符，必须重构；现有历史数据留作参考。
2. 一次分析使用同一数据读取视图，下一次分析读取后续已提交的数据。候选方案是 SQLite WAL 下为分析维护短暂只读事务；必须验证多线程、进程、澄清及大纲暂停后的连接生命周期、写入兼容性和 WAL 增长。若无法安全保证一致性，应显式失败，不能混用多次读取结果。临时 SQLite WAL 验证了读事务可保持旧结果且下一事务读取新结果；未验证 Agent 端到端。
3. 保留现有白名单方法并统一采用全量主张口径，不再要求 core/potential 精选子集。方法、字段、参数、空值和错误契约必须逐项映射，明确每项方法的过滤范围、去重单位及分母；不能归属产品的主张单独披露，`posts.tags` 永不进入统计和模型上下文。
4. 主张复合键为 `(post_id, run_id, claim_id)`，证据再加 owner_kind/owner_id/idx；实体关联先去重。产品链接没有 run_id 且同帖多运行时拒绝受影响查询。引文按 06 报告严格匹配，说明验证状态；未通过不冒称已回挂。Claim 引用标识与现有门禁的对接方案由工程设计并测试，不要求用户维护数据版本。
5. 正式报告每次生成均由人审查大纲，通过后自动执行并发布（用户选择方案 B），保留数字溯源。候选实现：已完成管道处理的数据变更触发更新，大纲审查及自动门禁通过后原子切换正式报告；重复事件合并，失败时保留已发布报告并记录错误。触发时机、冲突、检查和失败恢复必须测试，不能虚构人工审阅记录。

接口草案：输入为动态数据库位置、产品/议题及分析参数；输出为覆盖范围、统计值、口径、引用主张复合身份、证据来源及匹配状态。对外响应保留或迁移既有版本字段的方式、类型、错误及 auto-030/031/032 兼容性须以测试验证。用户明确取消其他负责人审阅；文件修改由本 Change 的 Codex 串行负责。

### 全量口径与逐次大纲审查

本次分析统一采用全量主张口径，原 `core/potential` 筛选不是本次要求。已有方法名称及结果中涉及“精选”的文案、筛选、输入输出与验收必须同步调整；全量仍按用户指定的产品、议题、时间等条件过滤，未能确认产品归属的主张单列，不归入具体产品。

用户选择逐次大纲审查方案 B：每次报告先由人审核大纲，再自动执行并在数字溯源等门禁通过后发布，因此新数据到正式报告发布之间仍需要大纲审查。具体触发及失败处理须经测试验证。

### 已核查的数据字段与初步适配

- `post_extractions` 以 post_id 确定当前通过的 run；`extracted_claims` 的主键为 `(post_id, run_id, claim_id)`，`extracted_evidence` 再加 `(owner_kind, owner_id, idx)`。产品链接 `claim_product_links` 没有 run_id；对涉及同帖多 run 的产品范围，现阶段访问层拒绝查询，避免猜测链接属于哪个 run。
- 产品关联使用 `entities.entity_id` 及子节点；先用 EXISTS 限制关联主张，避免多个实体和证据造成主张重复。`sentiment='负面'` 的主张数除以该议题主张数；帖子数按 post_id 去重。此口径为产品关联主张，不能冒充 06 报告的已回挂无比较精选子集。
- `posts.title/source_url/published_at` 用于证据来源，绝不读取 `tags_json`；引文保留 block_id/source_type/quote，验证状态未重算时为 `not_revalidated`。原报告 strict 和抽取规范化匹配结果必须分开表达。
- 现有 auto-030/031/032 的语义视图、任务简报、报告门禁将精选数据和旧版快照绑定；不得仅替换路径或重用“精选且已回挂”的标签。完整字段类型、错误和兼容方案须经验证；独立的数据源模块尚未接入产品。

### 数据层对账（2026-10-30）

原数据库经哈希前后核对复制至 `.local/auto035-pipeline-a45e3f11.sqlite3`；测试校验来源结构、摘要及只读连接。小米 SU7 及子实体关联的 18,144 条主张与报告所述总量一致；价格与成本议题 3,559 条、负面 361 条，比例 0.10143298679404326，以单独 SQL 去重复算一致。增量帖 `116480566`、run `04d-incr-qwen3.7-plus`、Claim `C1` 的帖子与证据关联行和独立 SQL 一致。记录见 `.local/auto035-source-verification.json`。这仅证明数据层对账，不代表证据重新回挂或模型语义验收，也未验证现有 Agent 接入。

### 动态数据接口验证（2026-10-30）

`LivePipelineSession` 对每个会话开启只读事务，允许正常 WAL、校验必需结构并序列化跨线程读取；新增 HTTP `/api/pipeline/stats`、`/api/pipeline/claims`、`/api/pipeline/evidence`，数据源由 `AUTOINSIGHT_PIPELINE_DB` 指定。证据按当前重建的 03 文本块或图片描述执行 06 字符串回挂，标明来源类型；重建的当前块不保证等于历史抽取输入。15 项动态来源、证据和接口测试通过；包括这部分在内的 54 项来源/接口/现有服务回归通过。`127.0.0.1:8001` 的独立实例对真实数据库验证了价格与成本统计：3,559 条主张、361 条负面。HTTP 每请求分别开启事务，尚不满足跨请求的 Agent 运行一致性；深度分析、任务简报、报告门禁、自动发布和全部方法尚未接线。

本轮新增 `research/live_methods.py`，在实时会话上提供 10 个既有方法 ID 的全量关联主张实现，以及 `/api/pipeline/method` 测试接口。真实数据库的方法烟测、非法参数检查、产品维度去重 SQL 对照和两个维度交叉计数检查通过；这些测试不覆盖所有数据边界或现有 Agent 工作流，旧进程需重启后才加载新增接口。`curated_sentiment_mix` 是为兼容保留的旧 ID，实际口径为全量关联，不能以名称推断为精选。

新增 `LiveAnalysisContext` 将任务简报、10 项方法和数据读取绑定至同一事务；在真实数据库临时副本上模拟暂停期间写入，新记录对原上下文不可见而对新上下文可见。`ReportSession.drop_session` 增加资源释放能力，覆盖完成/失败/清理时可调用；相关 24 项上下文、生命周期及既有大纲门禁测试通过。当前 `ReportSession` 尚未创建或使用该上下文，不能声称现有产品已接入。

新增 `research/live_verify.py` 在同一事务重放方法并复算负面比例；证据引用必须至少有一条引文且该主张全部引文通过 06 匹配。篡改比例和部分引文不匹配会被拒绝。来源、方法、上下文、证据、HTTP 和现有大纲门禁共 42 项测试通过。此复核尚未接入报告门禁，且重放不代替独立 SQL 或语义验收。

后续实施进展：实时报告会话、方法、沙箱、引用登记和大纲确认后的自动发布路径已在代码中接线；隔离测试覆盖门禁拒绝及保留上一份报告。实时上下文现可从表单接收时间范围，统计、观点、证据及沙箱在同一读取事务中使用该范围，报告门禁要求声明起止日期；2026 年 8 月的价格议题计数与独立 SQL 一致，71 项相关回归及后续 5 项定向测试通过。自然语言时间要求是否总能转换为过滤条件尚未验证；旧报告检索在实时对话中暂时关闭。数据变更自动触发、并发去重和恢复尚未完成，不得据此宣称自动更新已验收。测试进程须重启才能加载新代码；模型语义准确性仍未测量。

真实实例：用户确认大纲后 Qwen 运行，报告 `95224d522840` 自动门禁初次拒绝、修订后通过并在本地发布。复核发现正文将 3,559 条的价格议题描述为“仅次于”2,349 条的品牌议题，且存在样例向整体概括的表述；报告已标记 `withdrawn_quality`，原文与 provenance 保留。9 个引用 ID 均在本次证据登记中，证据均为文本且匹配，但一段正文引文的引号字符与证据不一致。代码增加对带紧邻引用标识的引文逐字检查，19 项门禁相关测试通过；该检查不证明所有引用写法或语义正确。真实实例未通过质量验收，不算任务 4.3 完成。

## Risks / Trade-offs

- [报告哈希与现有数据库不同，run 策略需确认] → 独立核对血缘和输入统计，不声称与报告字节相同。
- [实体关联或多证据导致重复] → 以复合键手算/独立 SQL 复核，并测试多产品、多 run、多证据。
- [旧工具使用精选子集而新库统一全量] → 同步更正名称与口径，逐项验证既有方法的结果及历史可比性；不得将全量标作精选。
- [抽取语义准确率未知] → 标明 NOT_MEASURED，结构校验不代表人工语义验收。
- [动态数据变更导致分析内部不一致] → 同一次分析使用一致读取视图，验证暂停及并发写入。
- [自动报告失败或覆盖有效结果] → 建议通过门禁后原子更新，失败保留现有报告；具体处理待审阅。

## Migration Plan

适配实时数据访问与所有现有方法→并发和一致性验证→运行一次 Qwen Agent 工作流及自动报告验证→代码审阅。实施与验证在隔离本地环境进行，不向外发布。
