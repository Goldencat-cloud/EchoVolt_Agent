# Spec Delta

## Purpose

使 Deep Agents 能直接读取持续更新的新离线管道数据，提供有明确统计口径和来源证据的查询，保持单次分析一致并支持正式报告自动更新。

## ADDED Requirements

### Requirement: 新管道数据直接访问

系统 SHALL 只读访问动态更新的新管道数据，不得在每次提问时将其转换成旧快照格式或要求用户维护固定版本。缺少必需结构时 MUST 显示失败原因，不能静默使用旧数据。

#### Scenario: 数据有效
- **WHEN** 数据库具备必需标准化视图和证据表
- **THEN** Agent 查询使用新管道数据并注明统计口径。

#### Scenario: 数据不完整
- **WHEN** 选择缺少证据表或规范化视图的数据库
- **THEN** 系统拒绝读取并说明缺失项。

### Requirement: 单次分析数据一致

一次分析的统计、证据、任务简报和报告 SHALL 使用一致的数据读取视图；新数据提交后 MUST 在下一次分析中可见，不要求维护固定版本。

#### Scenario: 分析期间新数据入库
- **WHEN** 一次分析开始后新数据完成入库
- **THEN** 本次分析保持一致，下一次分析读取已完成处理的新数据；无法保证一致时明确失败。

### Requirement: 统计与证据可复核

查询结果 SHALL 标明统计单位、分母和过滤范围；观点证据 MUST 保留来源主张及原帖定位信息，按 06 报告规则检查引文并注明状态，无法回挂的证据不得冒充已核验。

#### Scenario: 产品主张聚合
- **WHEN** 查询某产品与议题的观点和负面比例
- **THEN** 返回计数、分母和明确粒度，并避免实体关联与多条证据造成重复计数。

#### Scenario: 证据下钻
- **WHEN** 用户或 Agent 查看某条观点的证据
- **THEN** 返回对应原文、帖子标识、来源主张标识及 06 规则检查状态；不可定位时说明限制。

### Requirement: 保留分析口径和方法

系统 SHALL 保留现有分析方法并使用全量主张口径，明确每项方法的过滤条件、范围和分母；不再要求 core/potential 精选子集口径。不能确定产品归属的主张 SHALL 单独披露，不得猜测归类。

#### Scenario: 使用既有方法分析
- **WHEN** 用户通过既有分析方法查看某一议题
- **THEN** 系统按声明的全量范围与过滤条件返回结果，并明确统计分母，不得标为精选子集。

#### Scenario: 产品归属未知
- **WHEN** 某些主张没有可确认的产品关联
- **THEN** 系统单独披露这部分数据，不将其推定为某一产品。

### Requirement: 多运行归属不明确时拒绝

同一帖子有多个抽取运行且产品关联无法确定属于哪个运行时，系统 MUST 拒绝受影响查询并说明原因。

#### Scenario: 多运行关联无 run 标识
- **WHEN** 查询涉及多个运行且无法判定关联归属的帖子
- **THEN** 系统返回明确错误，不猜测归属。

### Requirement: 发布与数据边界

正式报告每次生成 SHALL 经过人工大纲审查，通过后自动执行并发布；系统 MUST 保留数字溯源门禁。分析 MUST NOT 使用 posts.tags 作为统计或模型输入。

#### Scenario: 正式报告自动更新
- **WHEN** 满足经审阅的触发条件、人工大纲审查通过且报告通过必需门禁
- **THEN** 系统自动执行并更新或发布正式报告，无须另行人工发布。
