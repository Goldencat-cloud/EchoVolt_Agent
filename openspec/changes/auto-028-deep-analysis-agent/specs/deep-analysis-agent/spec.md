# Spec Delta

## Purpose

让实时分析从"模板化查表"升级为"代码解释器驱动的深度分析"：Agent 按四阶段工作流（探索数据 → 分析草案 → 执行分析代码 → 出报告）处理开放性问题，同时严守语义层数据边界与确定性校验。

## ADDED Requirements

### Requirement: 上下文对话与按需在线分析

统一提问入口 SHALL 将所有消息交给同一个会话 Agent，由 Agent 根据上下文自主决定直接交流或使用统计查询、观点证据、已发布报告检索及语义层代码分析工具；MUST NOT 先调用独立意图分类器，也 MUST NOT 为互动分析强制要求报告工作流计划。代码分析 SHALL 继续受语义层与沙箱安全边界约束。完整研究报告只在用户明确请求时进入报告生成流程。

#### Scenario: 解释上一轮的统计结果

- **WHEN** 用户在统计回答后追问“你怎么得到这个结果的”
- **THEN** Agent 使用会话中的上一轮口径、统计与证据解释结果来源，不重新套用其他议题的模板答案

#### Scenario: 需要开放式分组分析

- **WHEN** 用户询问观点在多个体验或用户阶段中的分布，且预置统计不能直接回答
- **THEN** Agent 可按需调用代码解释器分析预载语义数据，并只报告代码输出支持的结论

#### Scenario: 普通交流无需调用工具

- **WHEN** 用户问候、感谢或询问助手能力
- **THEN** Agent 直接自然回应，不显示固定分类话术，也不执行无关统计

#### Scenario: 数据不支持或工具失败

- **WHEN** 所需维度不受支持、没有可用证据或工具执行失败
- **THEN** Agent 说明具体限制或错误，不虚构分析结论

### Requirement: 语义层数据边界

Agent 及其生成的分析代码 SHALL 只能访问语义层关系（`semantic_*` 视图：议题口径指标、精选观点事实、观点证据、帖子产品范围、快照元信息）；原始表 MUST NOT 对 Agent 层暴露。方法执行前与校验时 SHALL 双重校验 SQL 引用的关系。

#### Scenario: 非语义关系被拒绝

- **WHEN** 任何方法或生成代码尝试引用语义层之外的表
- **THEN** 执行被拒绝并说明"仅可访问语义层视图"，该结果不进入报告

### Requirement: 代码解释器沙箱

Agent 生成的分析代码 SHALL 在隔离子进程中执行：禁止 import 与危险调用，pandas I/O 入口封禁，仅预载语义层数据框可用； SHALL 有超时与输出上限。工具运行错误 SHALL 作为消息回传给 Agent 自行纠正，MUST NOT 中断整体流程。

#### Scenario: 生成代码含 import

- **WHEN** Agent 提交的分析代码包含 import 语句
- **THEN** 沙箱拒绝并返回错误说明，Agent 读取错误后修正重试，流程继续

#### Scenario: 深度报告产出

- **WHEN** Agent 完成四阶段工作流
- **THEN** 报告以 Markdown 提交并落盘，附分析日志（工具调用/代码/输出），数字可追溯到代码结果

### Requirement: 深度分析失败显性化

深度分析不可用（模型未配置、执行失败或未提交通过门禁的报告）时，系统 SHALL 将任务标记为失败并显示可理解的原因与重试方式；MUST NOT 自动切换到确定性分析管线并将结果显示为深度分析成功。确定性分析端点 SHALL 仅在用户显式选择时运行。

#### Scenario: 深度分析失败

- **WHEN** 深度 Agent 不可用或未能完成报告
- **THEN** 任务显示失败与重试提示，且不创建或伪装成深度报告

#### Scenario: 用户显式选择确定性分析

- **WHEN** 用户明确调用确定性分析入口
- **THEN** 系统运行确定性分析并标注该结果来自确定性管线
