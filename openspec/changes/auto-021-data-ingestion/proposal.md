# Proposal

## Why

现有帖子、用户和产品工具已经能取得数据，但输入绑定个人路径、增量状态依赖旧 Excel，帖子新版解析丢失有序图文且失败可能被解释成空结果。需要先建立一个可以离线回放、迁移恢复、逐条追溯的数据接入模块，再继续下游抽取和 Agent 建设。

## What Changes

- 在独立的 `offline_pipeline/` 目录建设一个数据接入模块，内部拆分 collect、normalize、quality、storage，共用配置、任务状态和日志，不重复实现 CLI/MCP 业务编排。
- 同时支持帖子、用户、车系及车型配置；新帖可触发缺失或到期用户资料采集，产品采集显式指定车系 ID。
- 原始响应先保存，标准化结果后入库；保留字段出处、质量问题、时间精度和帖子内有序内容，不静默丢弃失败或低质量记录。
- 提供历史 CSV 导入、保存响应离线回放、有限在线采集三种明确模式。无法从旧 CSV 恢复的信息标记未知，不伪造 HTML 或图文顺序。
- 采用8张核心表：posts、users、product_specs、product_parameters、source_snapshots、collection_runs、collection_failures、collection_checkpoints。业务表保留当前数据，历史原始材料不可变保存；不维护实体/观察/任务多层表。CSV不再充当状态数据库。
- 提供统一异步 HTTP API、固定依赖及 Docker 单应用运行方式；采集器为内部普通模块，不依赖 MCP。第一版只暴露创建、状态、恢复、取消四个任务接口；CLI只保留部署、导入、回放和运维入口，不迁入画像统计或车型对比等旧工具。网络采集默认关闭，测试默认不联网，不要求 Qwen 或个人开发工具配置。
- 不覆盖当前 9701 帖、V2.3、归一、报告或历史 ZIP。Owner后续明确排除旧工具新增127帖，当前存量库仅保留9994帖，回放不得将被排除的存量记录带回。

## Capabilities

### New Capabilities

- `forum-data-ingestion`：汽车之家帖子、用户及产品数据的采集、基础规范化、质量检查、来源保留、版本化入库、恢复与可迁移回放。

### Modified Capabilities

无。2026-10-21 当前根的正式 specs 清单为空；交接包中的历史规范副本是参考资料，不视为本根已经验收的要求。

## Impact

- 预计新增 `offline_pipeline/` 下的代码、配置、契约、测试和部署说明；不修改已有 `tools/`、测试、分析结果及其他 Owner 的 Change。
- 已确认首版方向：Python HTTP 服务 + SQLite 单写入者 + 内容寻址文件快照；不在本轮同时维护第二套数据库实现。HTTP服务默认仅监听本机，业务和存储共用唯一核心。
- Docker 用于固定程序环境；数据库和原始材料独立持久化并通过备份迁移，不能把 volume 存在等同已经验证恢复成功。
- 网络接口包括站点使用的 HTTP 接口与 HTML 页面；不声称它们是获官方承诺的开放 API。不增加绕过验证、代理轮换或破解反爬逻辑。
- 本轮不接入外部事件工具、Deep Agents、RAG、Qwen、语义抽取、车型语境归一、主题模型、图片 CLIP 策展或图片描述。图片本体下载和完整图片处理由后续阶段承担，本模块保存资源引用及其顺序。
