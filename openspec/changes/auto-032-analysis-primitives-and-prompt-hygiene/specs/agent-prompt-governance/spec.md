# Spec Delta

## Purpose

治理深度分析 Agent 的提示与技能文本：硬约束单一事实源、静态层与动态数据各归其位，消除"数据版本更替后静态指令变错"与"多处规则漂移"两类持久风险，同时减少模型可见文本中的无效内容。

## ADDED Requirements

### Requirement: 硬约束单一事实源

同一硬约束（如"计划仅可提交一次""失败后一次性修正全部字段"）SHALL 只在一处完整表述并以机制强制：工具代码是最终执法层；Agent 可见的说明文本（system prompt、技能文件、工具说明）MUST NOT 复述其他层已强制的行为规则，只能以简要引用指向责任层。

#### Scenario: 同一硬约束不再多处重复

- **WHEN** 对 Agent 可见静态文本做一致性检查
- **THEN** 任一硬约束在静态文本中只有一处完整表述，其余位置（若有）仅为指向该处的引用

#### Scenario: 规则仍被机制强制

- **WHEN** Agent 在计划获批后再次调用计划提交
- **THEN** 工具层返回已提交错误（行为与瘦身后一致），不依赖文本复述来阻止

### Requirement: 静态层不得携带数据版本相关事实

字节稳定的静态提示层（system prompt、技能文件、工具说明中构成缓存前缀的部分）MUST NOT 包含随数据快照或业务裁定变化的业务事实，包括但不限于：具体分析主体品牌名、数据临时/占位状态标识、议题枚举值。此类事实 SHALL 由任务简报（动态层）承载并在每次运行时注入；静态层对主体的表述 MUST 使用与快照无关的指代（如"当前分析主体，见任务简报"）。

#### Scenario: 更替快照后无需修改静态技能

- **WHEN** 快照数据版本更替或分析主体变更
- **THEN** 静态提示层文件内容不变，Agent 仍从任务简报获得正确的主体与数据状态声明

#### Scenario: 报告主体声明来源为动态简报

- **WHEN** 深度分析运行并生成报告
- **THEN** 报告中的分析主体与数据状态声明可回溯到该次运行任务简报中的动态注入内容

### Requirement: Agent 可见文本剥离内部工单引用

Agent 可见的静态文本 MUST NOT 包含内部工单或变更编号（如 auto-0NN 模式）；变更溯源信息 SHALL 仅保留在面向开发者的代码注释与 OpenSpec 工件中。

#### Scenario: 静态检查无内部工单号

- **WHEN** 对 Agent 可见静态文本执行内部编号模式检查
- **THEN** 未发现任何内部工单或变更编号

### Requirement: 静态层一致性锁定测试

上述治理规则 SHALL 由确定性测试锁定：静态层一致性检查（单一表述、无快照事实、无工单号）MUST 纳入现有提示缓存契约测试体系，任何违反项导致测试失败。

#### Scenario: 违反治理规则的文本变更被测试拦截

- **WHEN** 静态层新增复述硬约束的文本、写入具体品牌名或内部工单号
- **THEN** 一致性测试失败并指出违反的文件与位置
