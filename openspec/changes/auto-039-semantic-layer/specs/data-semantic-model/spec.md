# Spec Delta

## Purpose

定义业务数据在进入分析之前必须被声明成什么样：有哪些数据集、每个数据集一行代表什么、谁能连谁、每个数字属于哪一级样本、指标怎么算。它使"一个数字的含义"成为可校验的结构，而不是散落在代码与文案里的约定。

## ADDED Requirements

### Requirement: 数据集必须声明粒度与主键

每个对 Agent 可见的数据集 MUST 声明其粒度（一行代表什么业务单位）与主键。粒度取值 MUST 来自封闭集合：`claim`（观点）、`post`（发言）、`mention`（帖子×产品提及）、`product_node`（产品层级节点）、`user`（发言者）。

#### Scenario: 数据集缺少粒度声明
- **WHEN** 模型加载时某个数据集未声明 `grain` 或 `primary_key`
- **THEN** 加载 MUST 失败，并指出缺失的数据集与字段名

#### Scenario: 混合粒度的数据集
- **WHEN** 某数据集声明的同时包含观点级与帖子级度量
- **THEN** 加载 MUST 失败，并提示拆分为独立数据集

### Requirement: 实体关系必须声明基数与方向

模型 MUST 声明数据集之间的每条连接路径及其基数（`one_to_one`、`one_to_many`、`many_to_one`、`many_to_many`）。查询编译 MUST 依据声明判断连接是否放大行数。

#### Scenario: 经过多对多关系的聚合
- **WHEN** 查询请求按产品维度聚合观点级指标，且该路径经过 `many_to_many` 关系
- **THEN** 编译 MUST 先将事实聚合到声明的粒度再连接，结果行数与未连接时一致

#### Scenario: 引用未声明的关系
- **WHEN** 查询需要连接两个未声明关系的数据集
- **THEN** 编译 MUST 以 `GRAIN_CONFLICT` 拒绝，而不得自行推断连接条件

### Requirement: 口径阶梯必须作为一等对象声明

模型 MUST 声明有序的样本口径阶梯，每一级 MUST 具有名称、谓词、规模与来源（`rule` 或 `frozen`）。级与级之间 MUST 为包含关系，且 MUST 能回答"某一级包含多少条"。

#### Scenario: 查询口径阶梯
- **WHEN** 调用方请求语义目录
- **THEN** 返回 MUST 包含全部口径级的名称、规模、来源与相对顺序

#### Scenario: 使用未声明的口径
- **WHEN** 查询引用一个不在阶梯中的口径名
- **THEN** MUST 以 `UNKNOWN_POPULATION` 拒绝，并列出可用口径

#### Scenario: 冻结口径不可由规则重算
- **WHEN** 某口径级的来源声明为 `frozen`
- **THEN** 该级成员 MUST 由构建期导入确定，构建 MUST NOT 尝试用规则推导，且目录 MUST 如实标注来源

### Requirement: 指标必须声明类型、口径、粒度、可加性与可用维度

每个指标 MUST 声明：类型（`simple`、`ratio`、`derived`）、所属数据集、口径级、计算粒度、是否可加、允许的维度集合。比率型指标 MUST 分别声明分子与分母。

#### Scenario: 查询未开放的指标维度组合
- **WHEN** 请求的维度不在该指标的允许集合内
- **THEN** MUST 以 `INVALID_DIMENSION_FOR_METRIC` 拒绝，并返回该指标允许的维度列表

#### Scenario: 跨口径引用同一指标名
- **WHEN** 两个指标的业务含义相同但口径级不同
- **THEN** 它们 MUST 是不同的指标标识，且各自声明口径级；系统 MUST NOT 允许一名多口径

#### Scenario: 不可加指标参与横向汇总
- **WHEN** 请求对声明为不可加的比率型指标做跨分组求和
- **THEN** MUST 拒绝并在响应中说明正确做法是先取分子分母再计算

### Requirement: 维度必须声明类型、枚举来源与空值语义

每个维度 MUST 声明类型（`categorical`、`time`、`entity`）、取值来源（动态取自快照或静态声明）、规范值与别名映射、空值语义。维度取值 MUST NOT 由模型静态编造。

#### Scenario: 枚举取值与快照不一致
- **WHEN** 请求使用的分类值不在当前快照的取值集合内
- **THEN** MUST 以 `INVALID_ENUM_VALUE` 拒绝，并返回可用取值与可能的规范值映射

#### Scenario: 别名归一到规范值
- **WHEN** 请求使用已声明的别名（如"混合"对应规范值"正负混合"）
- **THEN** 编译 MUST 按别名解析为规范值，并在响应中回显实际使用的规范值

#### Scenario: 时间维度覆盖不足
- **WHEN** 请求的时间区间超出该时间维度的覆盖范围
- **THEN** MUST 以 `OUT_OF_COVERAGE` 拒绝，并返回实际覆盖区间

### Requirement: 语义关系是唯一对 Agent 开放的数据面

Agent 与外部消费者 MUST 只能访问声明为语义层的数据集。暂存层与核心层的数据集、物理表名与连接信息 MUST NOT 通过任何工具、错误信息或描述暴露。

#### Scenario: 尝试访问非语义数据集
- **WHEN** 请求或沙箱代码引用未声明为语义层的数据集
- **THEN** MUST 被拒绝，且错误信息只说明"不可访问"，不回显物理名称

#### Scenario: 语义层的定义与物理存储解耦
- **WHEN** 物理表结构或存储文件发生变化但语义定义未变
- **THEN** 对外暴露的数据集名称、字段与口径 MUST 保持不变

### Requirement: 语义视图由模型生成

对 Agent 可见的视图定义 MUST 由模型声明生成，MUST NOT 由人工另写一份视图 DDL 与模型并存。

#### Scenario: 生成结果与模型一致
- **WHEN** 模型变更后重新生成
- **THEN** 生成的视图字段集合、字段类型与口径过滤 MUST 与模型声明逐项一致

#### Scenario: 存在手工维护的同名视图
- **WHEN** 生成过程发现目标视图存在但非本次生成
- **THEN** 构建 MUST 失败并提示冲突，而不得静默覆盖

### Requirement: 数据血缘与版本必须随产物记录

每次构建 MUST 记录模型版本、快照标识、源文件摘要与构建时间，并使这些信息可被任意查询结果引用。任意查询结果 MUST 能追溯到产生它的模型版本与快照。

#### Scenario: 查询结果携带版本
- **WHEN** 任意查询返回结果
- **THEN** 响应 MUST 包含模型版本与快照标识

#### Scenario: 模型变更后旧结果不可误认
- **WHEN** 模型版本变化后引用旧结果
- **THEN** 旧结果携带的版本 MUST 与新版本不同，据此可判断口径是否一致

### Requirement: 构建必须校验源文件完整性

构建 MUST 校验源文件的摘要与模型声明一致。摘要不一致时 MUST 拒绝复用已有产物并要求重建，MUST NOT 在源变化的情况下继续使用旧数据。

#### Scenario: 源文件变化而产物未重建
- **WHEN** 源文件摘要与已构建产物记录的摘要不一致
- **THEN** 构建 MUST 判定为陈旧并重建，或直接失败并说明原因

#### Scenario: 源文件缺失
- **WHEN** 模型声明的源文件不存在
- **THEN** 构建 MUST 失败并列出缺失文件，MUST NOT 以空数据继续

### Requirement: 口径阶梯规模必须由数值回归确认

每一级口径的规模与关键指标取值 MUST 由固定快照上的回归用例断言。规模变化 MUST 需要在用例中显式确认后才能通过。

#### Scenario: 上游重跑导致规模变化
- **WHEN** 重建后某口径级规模与回归基线不同
- **THEN** 回归 MUST 失败并输出差异，直至维护者显式更新基线

#### Scenario: 指标重定义导致数值变化
- **WHEN** 指标定义变化使既有查询结果改变
- **THEN** 回归 MUST 失败并指明受影响的查询与字段
