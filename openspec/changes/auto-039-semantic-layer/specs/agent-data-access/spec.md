# Spec Delta

## Purpose

定义 Agent 与其他消费者如何取数：先看目录知道有什么，再用一个统一协议查询，拿到数字的同时拿到它的口径、覆盖与版本；走不通时有可读的拒绝理由。它保证"问数"这一层只有一种问法，且每次回答都自带解释。

## ADDED Requirements

### Requirement: 目录必须一次返回全部可查询内容

系统 MUST 提供目录描述能力，一次返回数据集、指标、维度、口径阶梯、命名查询、覆盖区间与枚举取值。目录 MUST 包含每个指标的中文名、口径级与同义词，供自然语言映射使用。

#### Scenario: Agent 首次了解数据
- **WHEN** 调用目录描述
- **THEN** 返回 MUST 足以让调用方在不读取任何代码或文档的情况下构造一次合法查询

#### Scenario: 目录中的覆盖信息
- **WHEN** 目录包含时间维度
- **THEN** MUST 同时返回该维度的实际覆盖区间与粒度

### Requirement: 查询必须通过单一协议

一个查询 MUST 以结构化请求表达：指标集合、维度集合、过滤条件、时间区间与粒度、排序、行数上限。系统 MUST NOT 要求调用方提供 SQL、表名或连接条件。

#### Scenario: 合法查询
- **WHEN** 请求包含已声明的指标、维度与处于覆盖区间内的时间条件
- **THEN** 返回与请求维度组合一致的结果行，且不包含未请求的字段

#### Scenario: 请求包含 SQL 或物理标识
- **WHEN** 请求中出现原始 SQL 片段或物理表名
- **THEN** MUST 以 `INVALID_REQUEST` 拒绝，MUST NOT 执行

#### Scenario: 超过维度或行数上限
- **WHEN** 请求维度数或行数上限超过策略允许值
- **THEN** MUST 以 `LIMIT_EXCEEDED` 拒绝，并返回允许的上限

### Requirement: 结果必须随附口径、覆盖与版本

每个查询结果 MUST 携带：实际使用的口径级与计算粒度、受影响指标的规范值与可加性、结果覆盖情况（含样本量不足的分组）、模型版本与快照标识、本次查询的唯一标识。口径说明 MUST 由结构化字段生成，MUST NOT 依赖手写文案。

#### Scenario: 结果的可解释性
- **WHEN** 任意查询成功返回
- **THEN** 调用方 MUST 能仅凭响应判断该数字属于哪一级样本、以什么单位计算、是否可与其他分组相加

#### Scenario: 结果可被追溯
- **WHEN** 报告引用某个数字
- **THEN** 该数字 MUST 能关联到一个查询标识，并据此还原请求、口径与版本

### Requirement: 非法请求必须以类型化错误码拒绝

系统 MUST 以稳定的错误码拒绝非法请求，并在响应中给出可执行的纠正信息。错误码至少覆盖：未知指标、未知维度、指标与维度组合非法、未知口径、超出覆盖、粒度冲突、枚举取值非法、请求超限。

#### Scenario: 未知指标
- **WHEN** 请求包含未声明的指标名
- **THEN** MUST 返回 `UNKNOWN_METRIC` 并列出最接近的可用指标名

#### Scenario: 维度对指标非法
- **WHEN** 请求的维度不属于该指标的允许集合
- **THEN** MUST 返回 `INVALID_DIMENSION_FOR_METRIC` 并列出该指标允许的维度

#### Scenario: 错误信息不得泄露实现
- **WHEN** 任意错误被返回
- **THEN** 错误内容 MUST NOT 包含物理表名、文件路径或生成的 SQL

### Requirement: 样本量不足必须披露而非静默丢弃

当某个分组或时间切片的结果量低于策略阈值时，系统 MUST 在响应中标记该分组并保留数据，MUST NOT 删除该分组或据此外推。

#### Scenario: 薄样本分组
- **WHEN** 某分组的结果量低于阈值
- **THEN** 响应 MUST 在覆盖信息中列出该分组标识，数据本身仍返回

#### Scenario: 空结果
- **WHEN** 查询在合法条件下无匹配行
- **THEN** MUST 返回空结果集并附带不影响判定的提示，MUST NOT 以错误码拒绝

### Requirement: 跨口径引用必须被拒绝或强制标注

当一次结果或一份下游产物同时引用两个不同口径级的数字时，系统 MUST 拒绝该组合，或要求调用方显式声明该比较并随结果保留标注。

#### Scenario: 同一响应混用两个口径
- **WHEN** 单次查询请求的指标分属不同口径级
- **THEN** MUST 以 `POPULATION_MIXED` 拒绝

#### Scenario: 显式声明的跨口径对照
- **WHEN** 调用方以对照模式提交两个口径的独立查询
- **THEN** 两个结果 MUST 各自携带口径级，且对照关系 MUST 在响应中可识别

### Requirement: 既有命名查询必须保持可用

系统 MUST 支持以命名查询方式执行既有的固定分析组合，参数校验与返回字段 MUST 与既有调用保持一致；命名查询 MUST 是查询协议的封装，MUST NOT 另行实现一套计算逻辑。

#### Scenario: 沿用旧调用
- **WHEN** 调用方以既有名称与参数调用命名查询
- **THEN** 返回字段集合 MUST 覆盖既有字段，新增字段只增不改

#### Scenario: 命名查询参数非法
- **WHEN** 命名查询收到未声明参数
- **THEN** MUST 以 `UNKNOWN_PARAMETER` 拒绝并列出允许参数

### Requirement: 不得提供任意查询通道

系统 MUST NOT 向 Agent 暴露直接执行 SQL 的能力，也 MUST NOT 允许通过沙箱读取语义层之外的数据。沙箱可用的数据集 MUST 与目录中声明的语义数据集一致。

#### Scenario: 沙箱数据面与目录一致
- **WHEN** Agent 在沙箱中访问数据
- **THEN** 可用对象 MUST 只包含目录中声明的语义数据集及其字段

#### Scenario: 沙箱尝试读取外部数据
- **WHEN** 沙箱代码尝试读取文件、网络或未声明的数据集
- **THEN** MUST 失败且不泄露可用物理位置
