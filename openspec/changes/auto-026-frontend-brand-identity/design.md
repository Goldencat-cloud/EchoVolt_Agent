# Design —— AutoInsight 前端品牌设计方案 v1（待 Owner 评审）

## 1. 品牌定位

> **AutoInsight · 新能源洞察工作台**
> 一句话：把冻结的用户声音变成可复核的研究结论。
> 品牌隐喻：**"实验室里的研究报告"**——左边是仪器（对话分析），右边是文献（研究报告）。

**品牌人格三关键词**

| 关键词 | 含义 | 视觉转译 |
|---|---|---|
| 证据 | 每个数字有口径、每条观点有来源 | 数据密度、等宽数字、来源链接常显 |
| 精确 | 口径不混用、边界不夸大 | 细线分隔、标签系统、克制的强调色 |
| 仪器 | 分析是严谨的操作，不是聊天玩具 | 深色仪表外壳、发光状态点、点阵网格 |

**反面清单（MUST NOT）**：霓虹渐变堆砌、玻璃拟态滥用、营销式大标题、装饰性英文混排、emoji、圆角超大化（玩具感）。

| 令牌 | 值 | 用途 |

### 2.4 报告侧（文献材质，沿用 auto-023）

`--paper:#FAF9F6`、`--ink-doc:#23282C`、`--doc-accent:#14547A`、衬线标题。两侧通过顶栏统一品牌，内部材质刻意分区。

### 2.5 用色规则

- 渐变只允许出现在：主按钮、品牌字、激活导航项、用户气泡（4 处白名单）。
- 发光（box-shadow glow）只允许：状态点、Logo、面板标题标记（3 处白名单）。
- 一屏内强调色元素 ≤ 3 个；正文区域禁止使用强调色底。

## 3. 字体系统

| 层级 | 字体族 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|---|
| 显示 | system-ui + "PingFang SC","Microsoft YaHei" | 20px/1.4 | 700 | 页面主标题 |
| 标题 | 同上 | 16px/1.5 | 600 | 卡片标题、分组标题 |
| 正文 | 同上 | 14px/1.65 | 400 | 消息、报告摘要 |
| 辅助 | 同上 | 12px/1.5 | 400 | 元信息、口径说明 |
| 数据 | `ui-monospace,"SF Mono",Consolas` + `tabular-nums` | 随容器 | 600 | 所有统计数字、版本号、claim_id |
| 文献标题 | Georgia,"Source Han Serif SC","Noto Serif SC" | 随报告版式 | 700 | 右侧报告（auto-023 既有） |

规则：数字必须等宽对齐；中文正文不使用斜体；强调用字重和色彩，不用下划线（链接除外）。

## 4. 布局系统

- **栅格**：顶栏 76px 深色常驻；下方双栏工作台。左列对话 420px（280–620 可拖，localStorage 记忆），右列报告弹性填充。
- **间距基数 4px**：允许 4/8/12/16/24/40；卡片内边距 16，卡片间 12，分区间 24。
- **圆角**：输入/按钮 12px；卡片 14px；气泡 14px（外侧角 4px 表示方向）；标签 999px。
- **阴影三级**：`sm` 卡片浮起（0 2px 12px 7% 黑）；`md` 用户气泡/主按钮（0 4px 16px）；`glow` 仅限白名单发光。
- **动效**：统一 160ms ease；仅允许透明度/位移(≤2px)/阴影过渡；状态点呼吸 2.2s；禁用大位移和弹跳。
- **窄屏（<1024px）**：折叠为单栏 + 顶栏 tab 切换（既有行为）；触屏目标 ≥ 44px。

## 5. 组件规范

| 组件 | 规格 |
|---|---|
| 顶栏 | 品牌渐变底 + 底部 2px 光轨；导航为胶囊分段控件；版本为呼吸灯状态胶囊 |
| 用户气泡 | 品牌渐变底、白字、右下角 4px、右对齐、max-width 92% |
| 回答卡 | 白底细描边、分组小标题（12px 灰色大写字距）、内嵌统计/证据/说明三区 |
| 统计指标 | 渐变数字 + 等宽、口径一行小字、禁止裸数字无口径 |
| 证据卡 | 左侧 3px 强调线、标题+引文+来源链接+元信息四行结构 |
| 主按钮 | 品牌渐变、hover 上浮 1px 加深投影、active 复位 |
| 输入框 | focus 3px 光环；错误态红描边 + 三段式错误文案 |
| 分隔条 | 6px 热区、中央把手点阵、hover 变光轨 |
| 标签 | 999px 胶囊、accent-100 底；语义色仅"已发布/待审核/临时样本"三种 |
| 警示条 | warn-bg 底 + 图标 + 一句话边界说明（固定文案池） |

## 6. 文案规范（Voice & Tone）

### 6.1 命名与署名

- 产品名：**AutoInsight**；副名：**新能源洞察工作台**；不使用"AI 助手""小助手"等称呼。
- 页面自称"工作台"；回答署名"AutoInsight"。

### 6.2 语气

- 陈述句、给口径、给边界；禁止夸大（"强大""智能极速"）、禁止卖萌、禁止反问用户。
- 每个回答必须能回答三个问题：**数字哪来的（口径+版本）、证据哪来的（精选说明+链接）、什么情况下不成立（限制）**。

### 6.3 固定术语表（全站唯一写法）

| 术语 | 固定写法 | 禁用 |
|---|---|---|
| negativeShare | 负面声明占比（声明级） | 负面率、差评率 |
| negative_posts/posts | 负向帖子数 / 议题帖子数（帖子级） | 负面帖子占比 |
| core/potential 证据 | 精选证据 | 全部观点、用户声音全集 |
| data_version | 数据版本 · 临时样本 | 正式数据、最新数据 |
| 拒答 | 当前问题无法对应到快照中的议题 | 抱歉呢、这个问题难倒我了 |

### 6.4 错误文案三段式

`发生了什么（一句）＋ 原因/边界（一句）＋ 下一步（可操作）`。
例："问答暂不可用——报告问答模型未配置。静态报告仍可阅读，或直接用对话分析查数。"

## 7. 无障碍承诺（沿用 auto-025 基线）

正文对比度 ≥ 4.5:1（ink/canvas ≈ 12:1，soft/canvas ≈ 7:1）；键盘完成全部操作；焦点可见不被遮挡；状态不只靠颜色（呼吸灯+文字标签并存）；320px 可重排。
