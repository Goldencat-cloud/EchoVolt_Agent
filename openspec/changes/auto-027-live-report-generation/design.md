# Design —— 按需实时报告

## 1. 目标形态

```
用户提问
   │
   ├─ 意图=报告问答 ──→ 读参考报告全文 → 带引用章节的回答（引用可跳转）
   │
   └─ 意图=数据/议题 ─→ 实时分析报告（右栏页签自动切换并渲染）
                          │
                          ├─ 解析议题（LLM 意图 + 快照白名单 + 规则回退）
                          ├─ 只读工具：query_stats / query_claims
                          ├─ 组装结构化报告（观测事实/比较/证据/解释/限制/待验证）
                          ├─ 确定性门禁（report_gate）
                          └─ 门禁通过 → 渲染 + 落盘；不通过 → 不展示并给出原因
```

## 2. 报告结构（与离线管线同构）

沿用 `report_generator` 的 content.json 结构，因此门禁规则、审计与未来导出都能复用：

| 段 | 内容 | 数据来源 |
|---|---|---|
| F1 声量与占比 | negativeShare、声明级计数、帖子级计数、横向排名与中位数对比 | `query_stats`（全部议题） |
| F2 精选证据 | 最多 8 条负向观点：引文、来源链接、日期、观点 ID | `query_claims(limit=8)` |
| F3 覆盖边界 | 用户阶段标签分布、解释与限制 | `query_claims(limit=20)` 的 journey 字段 |

## 3. 关键决策

1. **复用门禁而不是新增校验**：实时报告与离线草稿用同一套 `report_gate`。好处是"能离线发布的报告，就能在线展示"，不会出现两套标准。
2. **先有结构、后有文字**：报告正文是确定性模板 + 工具原值，模型不参与正文写作（解释段固定标记为假设）。代价是文字偏模板化，收益是绝不出现无法复算的数字。
3. **议题必须落在白名单**：LLM 给出议题提示后仍要过 `known_aspects()` 校验；无法对应时返回 `unsupported_scope` 并列出可选议题，不生成"看起来像报告"的空壳。
4. **两个页签共存**：实时报告（本次生成）与参考报告（设计版）并存，用户可对照；参考报告是只读产物，服务端仅注入品牌皮肤，不改磁盘文件。
5. **落盘但不入库**：`reports/live/<id>/content.json` 可复现，`.gitignore` 已排除。

## 4. 接口

- `POST /api/report/live` `{question}` → 200 `{"generated":true,"report":{...},"gate":{...}}`；
  范围外 → 200 `{"generated":false,"reason":"unsupported_scope","suggested_aspects":[...]}`；
  门禁失败 → 422 `{"generated":false,"reason":"gate_failed","issues":[...]}`。
- 报告体字段：`title / question / aspect / data_version / snapshot_hash / generated_at / coverage_notice / findings[]`。

## 5. 前端

- 右栏页签：`实时分析报告`（默认）/ `参考报告（设计版）`；顶部状态位显示"正在生成 / 已生成 / 未生成"。
- 实时报告排版沿用品牌令牌：衬线标题（与文献材质呼应）、指标条、证据卡、解释/限制/待验证分区。
- 报告问答的引用点击时自动切到"参考报告"页签并定位章节。

## 6. 风险

- **[生成延迟]** 实时报告一次只做两次只读查询 + 门禁，毫秒级；意图解析另需一次模型调用（8s 超时回退规则）。
- **[模板化观感]** 正文确定性生成。若要更强的行文，需引入"模型写叙述 + 门禁校验数字"模式，本 Change 不做（数字校验必须能拦截模型改写）。
- **[与 auto-025 的关系]** 复用其工具与门禁，接口未变；auto-025 仍在实施中，二者共享 `08_semantic_services/` 目录，交集仅限门禁调用方式。
