# Spec Delta: deep-analysis-workflow

## Purpose

定义深度分析业务工作流的用户可见能力：结构化的意图澄清输入、计划前的数据探索、给人看与给 Agent 看的双层草案、图表数据产出，以及 HTML 报告交付。本能力与 `deep-analysis-agent`（门禁状态机与 Agent 行为，auto-030）互补：门禁何时拦、拦什么不在本能力范围。

## ADDED Requirements

### Requirement: 结构化澄清选项

系统 SHALL 提供分析对象与时间范围的结构化选项数据，且该数据 MUST 与深度分析 Agent 任务简报中的覆盖声明同源生成：分析对象清单来自当前快照的品牌范围（当前仅小米 SU7 一项，界面以多选形式呈现）；时间范围选项 SHALL 落在冻结快照覆盖区间内并标注约束。分析主题与具体问题 SHALL 由用户自由填写，系统 MUST NOT 为其构造预置选项；Agent SHALL 将自由填写的问题自行识别映射到语义层议题维度。

#### Scenario: 表单获取选项数据

- **WHEN** 用户打开深度分析前置表单
- **THEN** 分析对象多选控件仅呈现小米 SU7 一项，时间范围控件呈现快照区间内的可选切片，且不出现主题/子题的预置选项

#### Scenario: 自由填写问题被识别映射

- **WHEN** 用户在自由填写框输入"充电排队和家充桩安装哪个抱怨多"
- **THEN** Agent 将其映射到语义层既有议题（如"充电与补能"）并拆解子问题，而非要求用户从选项中重新选择

### Requirement: 计划前的数据探索

在起草分析计划之前，Agent SHALL 能按所选议题获取数据预览——该议题的样本量、时间分布与代表性观点——且该预览 MUST 由服务端确定性计算。探索产出的样本量信息 SHOULD 用于判断子问题的可行粒度；数据不足以支撑的子问题 SHALL 在草案中标注或剔除。

#### Scenario: 按议题获取预览

- **WHEN** Agent 在计划阶段请求"充电与补能"议题的数据预览
- **THEN** 返回该议题的精选证据样本量、按时间分布的计数与代表性观点，且口径标注与任务简报一致

#### Scenario: 样本不足的子问题被标注

- **WHEN** 某子问题在预览中显示证据样本量过低（如不足 5 条）
- **THEN** Agent 在草案中标注该子问题数据支撑不足或将其剔除，而非照常纳入执行

### Requirement: 双文档分析草案

分析草案 SHALL 包含两个层次：**大纲**（面向用户的人读结构——分析维度、每个子问题的业务表述与呈现方式）与**执行步骤**（面向 Agent 的结构化步骤——method、aspect、参数与可视化意图）。大纲审查卡片 SHALL 渲染大纲层；用户编辑大纲后，系统 SHALL 将编辑同步到执行层并重新通过确定性校验。执行层 MUST NOT 包含与大纲层矛盾的内容。

#### Scenario: 用户查看并编辑大纲

- **WHEN** 大纲审查卡片展示草案且用户删除其中一个子问题并修改另一子问题的表述
- **THEN** 审查通过后，执行层同步移除对应步骤、保留其余步骤的原有参数，且整个计划重新通过确定性校验

#### Scenario: 执行步骤携带可视化意图

- **WHEN** 某执行步骤的分析结果适合图表呈现
- **THEN** 该步骤标注可视化意图（如图表类型与数据维度），供报告阶段直接消费

### Requirement: 图表数据产出

代码分析工具 SHALL 支持在返回分析结果的同时返回图表数据（结构化 JSON：图表类型、数据维度与数值），且沙箱的禁 I/O 与其他约束 MUST 保持不变。图表数据中的数值与表格结果 MUST 同源——任何无法在分析结果中找到对应值的图表数值 MUST NOT 出现。

#### Scenario: 代码分析返回图表数据

- **WHEN** Agent 在代码分析中产出月度负面占比的图表数据
- **THEN** 返回结果同时包含表格数值与图表 JSON，二者数值一致，且报告渲染时可据此绘制图表

#### Scenario: 图表数值无法溯源时被拒

- **WHEN** 图表数据中出现分析结果里不存在的数值
- **THEN** 报告门禁拒绝该提交并要求修正，与正文数字的溯源规则一致

### Requirement: HTML 报告交付

深度分析完成时，系统 SHALL 在既有 Markdown 报告结构之上渲染 HTML 报告（正文分节 + 图表渲染），且 HTML 为结果视图展示与用户下载的交付格式。HTML 渲染 MUST NOT 改变报告内容本身——报告门禁的数字溯源、引用与结构校验 MUST 仍作用于渲染前的报告结构层。

#### Scenario: 下载物为 HTML 报告

- **WHEN** 用户在报告结果视图点击下载
- **THEN** 下载得到包含正文分节与可交互图表的 HTML 文件

#### Scenario: 渲染不绕过门禁

- **WHEN** 报告未通过门禁校验
- **THEN** 系统不生成 HTML 交付物，仅呈现失败原因与修订要求
