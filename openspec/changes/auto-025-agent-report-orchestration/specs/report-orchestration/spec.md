# Spec Delta

## Purpose

让比赛评委通过一个可访问的 Web 产品完成数据提问、定量下钻、原始观点核验与追问，展示可复核的对话式研究能力。

## ADDED Requirements

### Requirement: 上下文 Agent 按需选择回答方式
统一提问入口 SHALL 将用户消息和会话上下文交给同一个 Agent，由 Agent 直接回应或按需使用报告检索、只读统计、精选证据和代码分析工具。主提问入口 MUST NOT 依赖独立意图分类结果；MUST NOT 将含糊或越界输入静默转成无条件分析。互动分析 MUST NOT 被报告工作流计划门禁阻止；代码分析仍 SHALL 遵守语义层和沙箱边界。

#### Scenario: 追问上一轮结果来源
- **WHEN** 用户在数据分析后询问“你怎么得到这个结果的”
- **THEN** Agent 结合上一轮实际统计口径、查询结果与证据说明来源

#### Scenario: 自然语言指向报告
- **WHEN** 用户明确询问已发布报告中的某个结论
- **THEN** Agent 按需检索已发布报告并基于检索到的章节作答和引用

#### Scenario: 数据范围外的问题
- **WHEN** 用户询问当前数据不包含的信息
- **THEN** Agent 说明数据范围限制，不编造结果；仅在关键条件影响结论时请求澄清

### Requirement: 研究维度与指标具有业务定义
研究 brief SHALL 为每个指标声明计算单位、分母/口径、数据源与适用范围，并为每个分析维度声明字段来源、总体覆盖范围、缺失值含义和支持的方法。报告发现 MUST 引用 brief 中声明的问题、指标和维度；精选证据维度 MUST 清楚标记为子集，不得外推为总体结论。

#### Scenario: 生成研究报告
- **WHEN** Agent 根据研究 brief 分析一个问题
- **THEN** 其工作项和报告发现能映射到已定义的指标与维度，并注明总体或精选子集口径

#### Scenario: 维度不受数据支持
- **WHEN** 用户请求未在当前快照或方法目录中定义的维度
- **THEN** 系统说明数据不支持该切片，不生成看似精确的结果

### Requirement: MCP 复用只读研究语义层
系统 SHALL 提供标准 MCP 入口，暴露与 Web/Agent 相同口径的只读研究工具。MCP MUST NOT 接受任意 SQL、文件路径、代码或发布写操作；工具输入输出 SHALL 有界且包含口径、样本、数据版本和警示。

#### Scenario: MCP 查询统计
- **WHEN** MCP 客户端调用受支持的统计工具
- **THEN** 结果由现有确定性查询层生成并返回指标口径、数据版本和适用范围

#### Scenario: MCP 请求不受支持的操作
- **WHEN** 客户端请求任意 SQL、文件访问或报告发布
- **THEN** 工具不提供该操作并返回明确的协议错误

### Requirement: 数据驱动的报告生成
系统 SHALL 基于已冻结的数据快照和经团队定义的研究任务生成报告草稿；现有手写报告内容 MUST NOT 作为当期事实源。每项发现 SHALL 分开呈现可复算观察、比较条件、证据、解释与限制。

#### Scenario: 新快照生成报告草稿
- **WHEN** 团队对一个带版本的数据快照运行报告生成
- **THEN** 草稿依据研究任务和查询结果生成，标明数据版本、口径与证据来源，不复制旧报告结论作为事实

#### Scenario: 发现结构不完整
- **WHEN** 某项发现缺少比较条件、有效证据或适用限制
- **THEN** 草稿生成门禁将该发现标为不完整并要求修订，不把它作为已验证结论

### Requirement: 报告质量门禁与人工审核
报告 SHALL 经过确定性来源/结构校验和至少一名非作者队友的内容审核后，才可进入公开发布包；校验通过本身 MUST NOT 被表述为分析质量证明。

#### Scenario: 草稿未获审核
- **WHEN** 报告门禁通过但尚无非作者审核批准记录
- **THEN** 报告保持待审，不出现在公开发布目录，当前已批准版本继续在线

#### Scenario: 结论与数据冲突
- **WHEN** 发现的排序、数值或比较关系与确定性查询结果冲突
- **THEN** 系统阻止该草稿发布并指出冲突字段，修订后重新校验和审核

#### Scenario: 深度 Agent 报告进入正式发布
- **WHEN** 深度 Agent 提交报告且确定性门禁通过
- **THEN** 报告进入待审核发布队列；非作者队友批准并留下审核人、日期和审阅 commit 后，报告才替换公共报告与报告问答语料；未批准的报告只作为当前会话预览

#### Scenario: 仅提供已批准深度报告
- **WHEN** 用户请求 `GET /api/reports/published/latest`
- **THEN** 系统只返回当前快照版本下最新已批准报告；没有已发布报告时返回 404，待审或驳回报告不得通过该接口读取

### Requirement: 对话式分析闭环
系统 SHALL 支持用户以自然语言提出报告未覆盖的问题，并将其转化为受支持的统计查询与观点检索；回答 SHALL 区分统计事实、证据解释和建议。

#### Scenario: 从问题到发现
- **WHEN** 用户询问某议题的主要负面体验及其用户阶段差异
- **THEN** 系统返回对应统计、口径、样本量、分组结果与支持观点，并区分事实和解释

#### Scenario: 超出数据支持范围
- **WHEN** 问题涉及当前数据集不支持的属性或因果判断
- **THEN** 系统说明不可回答的原因，不生成无证据结论，并可提示可执行的替代查询

### Requirement: 深度分析计划与阶段约束
深度 Agent SHALL 在查询前提交结构化分析计划，将用户问题拆分为覆盖其子问题、议题和比较维度的工作项；每个工作项 SHALL 指定数据支持的分析方法、议题及是否需要观点证据。Agent SHALL 仅执行计划列出的工作项，且只有全部工作项和要求的证据完成后才可提交报告。系统 SHALL 限制计划工作项和成功工具调用次数。

#### Scenario: 多议题问题先拆解再执行
- **WHEN** 用户问题要求比较多个议题或用户维度
- **THEN** Agent 先提交分别覆盖这些问题的工作项；系统校验方法、议题和维度后才允许分析工具执行

#### Scenario: 计划未完成
- **WHEN** Agent 提交报告但一个或多个工作项未执行，或必需证据未取得
- **THEN** 系统拒绝提交并指出未完成的工作项；报告不得进入待审核队列

#### Scenario: 达到调用上限
- **WHEN** Agent 达到成功工具调用上限
- **THEN** 系统拒绝新的分析调用并要求其提交已有证据支持的报告，或明确报告无法完成

### Requirement: 深度分析失败显性化
深度 Agent 未能提交通过门禁的报告时，系统 SHALL 将任务标记为失败并向用户提供可理解的失败状态；MUST NOT 静默改走另一分析链路并将其显示为深度分析成功。

#### Scenario: 深度分析未提交报告
- **WHEN** Agent 结束但没有一份通过门禁的报告
- **THEN** 任务进入失败状态并显示重试指引；确定性分析仅可由用户显式选择

### Requirement: 统计结果确定性
系统 SHALL 由确定性查询逻辑计算统计数字；Agent MUST NOT 自行计算、改写或补造统计值。每项统计结果 SHALL 带有口径、数据版本、样本量和适用范围。

#### Scenario: 可复核的统计结果
- **WHEN** 用户请求指标、比例或分组比较
- **THEN** 返回数字可由当前数据快照和声明口径重算，且响应包含版本、样本量与适用范围

#### Scenario: 不足样本
- **WHEN** 查询切片低于配置的最小样本量
- **THEN** 系统标记样本不足并限制结论强度，不将结果表述为稳定规律

### Requirement: 观点证据回溯
系统 SHALL 为定性发现提供可核验的观点证据，包含引文、来源链接、观点表达边界及其与发现的关联；无支持证据时 MUST 明确说明。

#### Scenario: 发现有证据
- **WHEN** Agent 输出某项用户体验发现
- **THEN** 用户可查看支持该发现的观点引文、来源链接与表达边界

#### Scenario: 证据不足
- **WHEN** 检索结果无法支持生成的发现
- **THEN** 系统不呈现该发现，或明确标为证据不足

### Requirement: 多轮分析连续性
同一会话中的追问 SHALL 保留已确认的分析条件，并允许用户查看上一结论所用查询与证据；修改议题或筛选条件时 SHALL 展示当前生效条件。

#### Scenario: 沿结论追问
- **WHEN** 用户追问“这些观点主要来自哪个用户阶段”
- **THEN** 系统沿用上一轮议题与情感条件进行分析，并显示继承的条件

#### Scenario: 条件变更
- **WHEN** 用户要求比较另一议题或时间范围
- **THEN** 系统更新相应筛选条件，并在结果中说明本轮使用的条件

### Requirement: 报告与分析入口
部署产品 SHALL 提供报告阅读、报告问答与对话式分析入口；静态报告 SHALL 在分析服务暂不可用时仍可访问。

#### Scenario: 核心入口可用
- **WHEN** 用户通过部署链接访问产品
- **THEN** 用户可打开报告并进入问答或对话式分析

#### Scenario: 分析服务故障
- **WHEN** 问答或分析 API 不可用
- **THEN** 产品显示明确错误状态，报告阅读仍可使用

### Requirement: 响应式与无障碍交互
前端 SHALL 支持键盘操作和窄屏重排；状态、错误和数据含义 MUST NOT 仅依赖颜色表达，且页面 SHALL 保持可见焦点、清晰标签与足够文本对比度。

#### Scenario: 窄屏阅读
- **WHEN** 用户在 320 CSS px 宽视口浏览普通内容
- **THEN** 页面重排内容且无需双向滚动，主要功能仍可使用

#### Scenario: 键盘和状态反馈
- **WHEN** 用户仅通过键盘使用导航、分析输入和证据展开，或遇到加载/错误状态
- **THEN** 焦点可见且不被遮挡；状态可被辅助技术识别；错误保留用户已输入的问题并给出下一步操作

### Requirement: 新能源研究品牌一致性
工作台和嵌入报告 SHALL 使用一致的品牌色、字体、间距和信息层级；视觉表达 MUST 突出指标口径、比较对象、数据版本、分析维度和证据链，且适合新能源数据挖掘场景。

#### Scenario: 在工作台切换到报告
- **WHEN** 用户从分析界面打开报告
- **THEN** 报告与工作台共享品牌识别和可读性规则，数据图表及证据仍按研究内容呈现

#### Scenario: 浏览器窄屏展示
- **WHEN** 用户在窄屏浏览数据分析和报告
- **THEN** 品牌组件保持一致，图表与维度标签可读且不发生横向页面溢出

### Requirement: 内部术语与用户表达分离
系统 SHALL 将数据字段、工具、技能、工作流阶段等内部术语映射为面向业务用户的自然语言。指标说明 MUST 准确表达统计单位和分母；用户界面、分析回答与报告正文 MUST NOT 直接暴露内部字段名或工程术语，除非用户明确询问技术实现。

#### Scenario: 用户查看统计结果
- **WHEN** 用户查看负面观点占比和观点证据
- **THEN** 系统使用“负面观点占比（按观点条数）”“观点条数”“证据编号”等清楚表述，并说明帖子数是另一统计单位

#### Scenario: 用户查看分析状态或报告
- **WHEN** Agent 运行期间或完成后向用户展示状态、摘要或报告
- **THEN** 用户看到研究问题、数据分析、证据核对等业务步骤，不看到 `claims`、`journey`、`workstream`、工具名或技能名等内部词

#### Scenario: 用户明确询问实现细节
- **WHEN** 用户明确询问字段、工具或工作流如何实现
- **THEN** 系统可以解释内部术语，并同时给出其对应的业务含义

### Requirement: 分析与报告的从属关系
分析工作台 SHALL 作为产品的主入口；已发布报告是分析成果的阅读入口，不得与分析工作台作为并列主导航项。工作台 MUST 默认将可用空间用于当前任务；用户打开报告前 MUST NOT 常驻展示空白报告栏或占用空间的拖动分隔条。

#### Scenario: 默认进入分析工作台
- **WHEN** 用户打开工作台
- **THEN** 分析内容使用完整主区域，页面没有空白并列报告栏或可拖动竖条

#### Scenario: 用户打开报告
- **WHEN** 用户从分析页的次级操作打开已发布报告
- **THEN** 报告在主区域显示，并提供明确的返回分析操作

### Requirement: 部署与运行边界
部署版本 SHALL 通过 HTTPS 提供访问、具备健康检查，并从运行环境读取模型密钥；MUST NOT 将密钥写入仓库或客户端资源。公开展示内容 SHALL 经团队确认符合数据展示授权。

#### Scenario: 服务健康检查
- **WHEN** 部署平台请求健康检查
- **THEN** 服务返回可判定的健康状态，且不触发模型调用

#### Scenario: 未配置模型服务
- **WHEN** 模型端点或密钥未配置或调用失败
- **THEN** 系统返回可理解的不可用提示，不伪造回答，报告页面仍可访问

#### Scenario: 发布数据审查
- **WHEN** 团队准备将报告和观点证据部署到可访问链接
- **THEN** 发布内容及链接已由团队确认可用于比赛演示
