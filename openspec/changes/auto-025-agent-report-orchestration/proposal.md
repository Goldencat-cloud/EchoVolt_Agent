# Proposal

## Why

比赛要求提交可访问的智能体链接；团队由 3 名学生组成，项目处于 MVP 阶段，需要交付一个能从用户问题出发完成分析、举证和追问的产品。当前 06 的报告是上一版数据上的临时文档：脚本填充数字并渲染，但主要发现与解释由人维护，且正文存在结论与表格数值不一致的问题，不能作为正式产品报告或智能体的可信事实源。

## 产品需求与产品设计

### 产品定位

面向新能源汽车用户研究的对话式分析智能体。用户可阅读由数据快照生成并经团队审核的研究报告，也可提出报告未覆盖的问题；智能体调用受约束的统计和观点查询能力，返回有口径、样本信息和证据出处的发现，并支持沿分析条件继续追问。

### 报告从哪里来

报告基于 01–05 管线已冻结的结构化分析结果与来源证据生成，不以当前 `report.md` 或 `report.html` 的手写结论为底稿。团队维护的是研究任务定义（要回答的问题、指标口径、适用群体、比较维度、覆盖范围和质量要求），Agent 基于确定性查询与观点证据生成结构化报告草稿；团队复核后才发布。构建、渲染和数字填充代码可以复用，旧报告中的结论文案只作为待核查样例。

报告不是让 LLM 自由发挥：发现要由可复算统计、明确比较对象和可追溯观点支撑；数据事实、解释假设、建议分别呈现。MVP 在新快照上离线生成报告，经过审核后部署为静态报告；在线智能体负责报告问答与针对新问题的即时分析。第一版不做无人审核的自动发布。

### 目标用户与首要任务

- **比赛评委/演示观众**：快速理解数据发现，现场提出新问题并核验回答依据。
- **产品研究者**：探索议题、情感与用户阶段之间的差异，从总体指标下钻到具体观点。

MVP 首要任务：在同一产品链接中完成“读审核报告 → 提出新问题 → 查看统计与证据 → 追问或调整条件”的连续体验。

### 核心用户流程

1. 团队选择一个冻结数据版本和研究任务定义，运行报告生成流程。
2. Agent 通过分析工具探索声明过的议题、指标、切片与比较，产出结构化发现和报告草稿。
3. 生成门禁核对数字、口径、引用、证据和章节覆盖；失败时保留草稿并报告原因。
4. 团队成员核查结论、证据质量和解释边界，批准后生成可部署报告包。
5. 评委从报告进入问答或对话分析，提出报告未覆盖的问题。
6. 智能体返回确定性统计、证据观点、生效条件和适用范围；证据不足或问题越界时明确说明，不补造结论。

### 创新点

- **从数据生成研究发现**：Agent 依据研究任务定义和确定性分析工具生成新报告，不依赖人工预写发现段落。
- **从指标到观点的证据链**：报告和在线回答都可从汇总指标下钻到用户原话、来源链接与表达边界。
- **可控的多轮研究**：追问沿用并显示分析条件，支持更改切片继续探索。
- **可审查的生成过程**：每期报告记录数据版本、任务定义版本、提示词/模型版本、校验结果和审核状态。

### MVP 范围

- 报告生成草稿、团队审核与报告发布；报告问答和在线对话式分析三个入口，重点打磨分析闭环。
- 使用当前可用的冻结结构化数据；先核实观点数据、指标字段与授权，不重跑上游模型链路。
- Agent 只调用有限、只读、带 schema 的统计和观点工具；指标公式由代码确定，叙述由 Agent 基于工具结果组织。
- 研究任务定义覆盖有限但有代表性的议题与对比问题，质量优先于全量指标堆砌。
- 通过公网 HTTPS 链接部署已审核报告；提供健康状态、模型故障提示和静态报告回退。

### 本 Change 不做

- 通用指标平台、任意 SQL/文件访问、全量自动化数据采集和上游模型重跑。
- 多 Agent 协作、用户账户体系、无人审核自动发布。
- 跨期趋势和历史版本对比；仅保存本次发布的来源与审计信息。
- 将 LLM 自评、关键词命中或单一总分作为报告正确性的证明。

### 团队协作建议

3 人分别负责研究任务与报告审核、分析工具/Agent、Web 与部署；先冻结研究任务定义、工具 schema 和发布门禁，再并行实现。Owner 对报告结论、公开数据内容、产品范围和最终验收负责。比赛评分细则、云平台和可公开数据授权尚未在仓库证据中确认，实施前应由 Owner 补充或确认。

## What Changes

- 明确旧报告仅为临时样例和复用零件；建立从冻结数据、研究任务定义、Agent 分析草稿、确定性校验到团队审核发布的报告来源链。
- 将报告质量定义为可追溯发现：每项发现须绑定可复算数值、比较条件、观点证据和解释边界；不以文本流畅替代分析质量。
- 保留报告问答与对话式下钻，并通过公网产品提供统一入口。
- 将全量管线自动调度、无人审核自动发布、通用语义平台及跨期分析移至后续阶段。
- 将内部数据字段、分析流程和用户可见表达分开管理；采用单焦点分析/报告导航，避免默认空白报告栏挤占主界面。

## Capabilities

### New Capabilities

- `report-orchestration`：支撑报告生成、团队审核、问答和对话式分析共享数据口径，并约束统计确定性、证据回溯、多轮分析与部署行为。

### Modified Capabilities

- 无。

## Impact

- 只读消费 01–05 已冻结分析结果与观点证据；不在本 Change 重跑采集或上游模型任务。
- 复用 `06_reporting/agent-kb/` 的构建、渲染和数字填充零件，但重新审查报告内容结构与结论；不将现有报告文字直接当最终语料。
- 复用 `07_qa_agent/` 的报告问答行为，并接入 Web API；新增有限范围的分析工具、报告生成编排、审核/发布记录及前端。
- 深度 Agent 的报告直接接入同一审核/发布流程；门禁通过后进入非作者复核队列，批准后才成为公共报告与问答语料。
- 当前数据版本为临时样本，公开部署前需团队确认报告、引文和来源链接的展示授权。
