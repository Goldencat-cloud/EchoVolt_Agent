# 输入语料说明

本目录随仓库发布 1 份清洗后的论坛语料，供 `scripts/` 下的分析与评估脚本使用。

## 文件

| 文件 | 大小 | 行数 | 时间范围 |
|---|---|---|---|
| `汽车之家_小米SU7_深度清洗_clean_valid_imgid_curated.csv` | 45.26 MB | 9,701 条帖子 | 2022-10-28 ~ 2026-10-03 |

## 血缘与内容

- **来源**：汽车之家 小米SU7 论坛公开帖子，由主项目（comments_for_decisions）爬虫采集后，
  经 A1 采集 → A3 深度清洗（去噪/去广告/正文规整）→ A4 图片下载与策展 主链路产出，
  是该主链路的终版语料（主项目中同名文件位于 `data/processed/`）。
- **用途**：本工具只把它当作「时间轴刻度 + 评论文本池」：
  - `scripts/verify_research_tool.py`：仅读 `created_at` 的 min/max 作为调研时间窗；
  - `scripts/analyze_resonance.py`：按事件日期取前后窗口评论，让 LLM 判定「是否真在讨论该事件」；
  - `scripts/eval_influence.py`：按日聚合评论量，做伪事件对照与波峰对齐检验；
  - `scripts/make_judge_calibration.py`：抽样评论构建判定员校准集。
- **脚本实际用到的列**：`post_id`、`created_at`、`clean_text`（缺失时回退 `text_content`）、`title`。
  其余列（作者、地域、图片/视频 id 等）为上游管线保留字段，本工具不读取。

## 为什么随仓库发布

分析与评估脚本依赖真实评论分布才能复现 `outputs/eval/` 中的数字。为让仓库克隆后开箱可跑，
该文件（45.26 MB，未超过 GitHub 单文件 100 MB 限制）随仓库一并发布。

## 使用注意与合规

- 语料含**公开论坛的用户生成内容**，仅用于学术研究与方法的验证复现，**请勿用于商业用途**，
  也不要据此对个人或群体做画像、评价或传播。
- 如需换成自己的语料，所有相关脚本都支持 `--corpus <路径>`，只要 CSV 含上述 4 列即可，无需改名。
- 语料不含任何密钥或登录态信息（爬虫 cookie 文件 `club_auth.json` 未入库）。
